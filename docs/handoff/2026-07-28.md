## First five minutes after the update

macOS updates reboot, and two things did not come back on their own this morning:

```sh
familiar daemon status          # "launchd installed" is NOT "running" — check the pid
tailscale status                # came back Stopped, node key intact
```

- Daemon stopped → `~/Library/Application\ Support/Familiar/bin/familiar daemon start`
- Tailscale stopped → `tailscale up --timeout=30s --accept-routes`
  (plain `tailscale up` refuses unless you restate the non-default flag)

**Always pass `--data-dir` explicitly.** `familiar daemon install|start` takes it as a
**flag**; a positional path is silently ignored and it falls back to a cwd-relative
`./familiar_data`. Doing that from the repo pointed launchd at the wrong data dir
(node `3c782cd1`, empty queue) instead of the real one:

```sh
familiar daemon install --data-dir "$HOME/Library/Application Support/Familiar/data" --interval 60
ps -o command -p $(pgrep -x familiar)     # confirm the dir it actually launched with
```

That mismatch is also why `mesh roster` self-id (`3c782cd1`) has long disagreed with
`/local/worldview` node_id (`1c991bc6`). Two data dirs, never a bug.
