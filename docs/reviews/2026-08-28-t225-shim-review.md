# T-225 stdio shim — codex review findings (2026-08-28)

Codex's reciprocal review of `crates/shim` (branch `claude/t225-stdio-shim`),
returned across its restart exec session and the findings-recovery follow-up;
transcribed by the chair. Five findings, all open — repairs owed before the
shim can land.

1. **Repeated `initialize` to one long-lived child.** Every new familiar
   `Session` re-sends the handshake to the same child process, breaking the
   stdio lifecycle the child expects. `crates/shim/src/lib.rs:145`.
2. **No deadline on child stdout.** A silent child blocks the single serving
   loop indefinitely; the HTTP socket timeout does not constrain the child
   pipe. `crates/shim/src/lib.rs:78`.
3. **Same-ID misclassification.** Any child message bearing the awaited id is
   accepted as the response; MCP permits server→client requests before the
   final response, so a same-id sampling request can be relayed as the answer.
   Matching must require `result`/`error`, not merely `id`.
   `crates/shim/src/lib.rs:88`.
4. **Argv secret logging + token-file chmod race.** Child arguments are
   printed verbatim (may carry API keys) and the bearer file is chmodded only
   after writing — redact argv, create the key file atomically at 0600.
   `crates/shim/src/main.rs:69`, `crates/shim/src/lib.rs:196`.
5. **Missing hostile `Origin` validation** at the loopback HTTP fence.

Grounding cited: MCP 2025-06-18 lifecycle and transports requirements.
Codex's independent run of the compiled non-network subset: 8 passed; four
loopback tests were denied by its session sandbox (untested there, not red).
